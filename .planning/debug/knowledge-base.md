## cef-close-shutdown-dialog — closing a CEF wallpaper opened the Windows Shut Down dialog
- **Date:** 2026-11-26
- **Error patterns:** Shut Down Windows dialog, Windows'u Kapat, theme switch, CEF browser did not close in time, close timeout 5 s, renderer exit 0xffff7003, 0xc0000005, the renderer stopped missing, WM_CLOSE, Progman, DoClose, CloseBrowser
- **Root cause(s):** CEF's default DoClose (false) for a windowed browser makes CloseHostWindow post WM_CLOSE to GetAncestor(browser, GA_ROOT); our life span handler did not override DoClose; the wallpaper browser is a child of the desktop surface under Progman (raised layout), so the WM_CLOSE reached Progman (its WM_CLOSE is the Shut Down Windows dialog); nothing destroyed the browser window, so the close timed out and the renderer crashed in cef::shutdown
- **Fix:** SpanHandler::do_close answers 1 for the wallpaper browser (popups keep the default); CefHost::close destroys the browser's own window once DoClose came (or after 3 s), pumps until OnBeforeClose or 5 s; window.close() from the page is ignored with a WARN; popup OnBeforeClose no longer marks the wallpaper closed (commit 5758edd0)
- **Files changed:** crates/sucrose-engine-cef/src/browser.rs, docs/FEATURES.md, docs/ARCHITECTURE.md, .planning/STATE.md
- **Why not caught:** no gate existed for this class: no test called the life span handler through CEF's function table, review did not check the DoClose contract, and no desktop run switched away from a CEF wallpaper before the 04-20 maintainer check
- **Recurrence guard:** crates/sucrose-engine-cef/src/browser.rs imp::tests::the_life_span_handler_never_lets_cef_close_the_desktop_window and tests::the_wallpaper_browser_never_lets_cef_send_its_close_message (plus the two close_step timing tests); KB pattern: any window hosted under Progman/WorkerW must never let a library send WM_CLOSE to its GA_ROOT

## cef-web-themes-stuck-loading — CEF web themes stuck on loading, CORS error, seek video invisible (GPU process crash, dropped web-security switch, missing Skip)
- **Date:** 2026-11-27
- **Error patterns:** Web theme stays on its loading screen on CEF only, WebView2 opens it, page loaded status=200, GPU process exited unexpectedly exit_code=-2147483645 (0x80000003) three times per start, Failed to create shared context for virtualization, GL_VENDOR Disabled, A WebGL context could not be created, three.js, SucrosePropertyListener is not defined, blocked by CORS policy, Web security may only be disabled if '--user-data-dir' is also specified, Range request past byte 0 fails, TypeError Failed to fetch, video with moov at the end never shows, seek fails, url-input black, Music Tunnel black
- **Root cause(s):** sucrose.exe, which CEF also runs as its GPU subprocess (D-036), had no application manifest with the Windows 10 supportedOS entry, so the GPU process CHECK-crashed on its first command buffer and Chromium disabled GL (no WebGL for any page); Chrome's BasicStartupComplete stripped --disable-web-security because CEF sets the user data dir only through PathService, never as --user-data-dir on the command line (CORS enforced); the CEF scheme handler did not implement CefResourceHandler::Skip, which CEF's StreamReaderURLLoader calls for every Range starting past byte 0, so those requests failed
- **Fix:** apps/sucrose/build.rs has the MSVC linker embed resources/windows/sucrose.manifest.xml into the sucrose binary only (/MANIFEST:EMBED, /MANIFESTINPUT:<abs path>, /MANIFESTUAC:NO; rust-lld and link.exe merge it themselves, no build dependency; non-MSVC Windows targets get a cargo warning); the CEF browser process appends --user-data-dir = root_cache_path unless the user's switches name one (None for in-memory caches); OriginHandler implements skip() (Stream::skip_to) and reports the bytes left after it (commit a0e22d9a)
- **Files changed:** apps/sucrose/build.rs, apps/sucrose/resources/windows/sucrose.manifest.xml, apps/sucrose/tests/manifest.rs, crates/sucrose-engine-cef/src/browser.rs, crates/sucrose-engine-cef/src/scheme.rs, docs/ARCHITECTURE.md, docs/FEATURES.md, .planning/STATE.md
- **Why not caught:** no gate existed for this class: no test inspected the built executable's manifest, the CEF GPU crash was logged only in CefRenderer-<slot>.log (not in Sucrose's logs) and recorded as cosmetic because software rendering still showed pages, the Range tests exercised the reply planner and WebView2 but never CEF's loader (which adds the Skip step), and Chrome's switch-stripping is logged only in debug.log beside the exe
- **Recurrence guard:** apps/sucrose/tests/manifest.rs the_sucrose_binary_declares_windows_10_compatibility (fails when the link args are removed); crates/sucrose-engine-cef/src/scheme.rs tests a_range_past_zero_is_already_at_its_start_when_cef_skips_to_it, a_whole_file_reply_moves_forward_to_the_skip_target, a_skip_behind_the_stream_or_past_its_end_fails, a_refusal_is_sent_whole_after_a_skip, the_handler_answers_cef_skip_through_its_function_table; crates/sucrose-engine-cef/src/browser.rs the_profile_folder_is_also_the_user_data_dir_and_in_memory_caches_have_none; KB pattern: when CEF misbehaves only in our build, grep CefRenderer-<slot>.log for "GPU process exited" and debug.log beside the exe for stripped switches, and compare the executable with CEF's sample executables (manifest, /STACK)

## webview2-certs-video-input — WebView2: certs frame late after Allow invalid certificates, video-clip page black, url-input ignores the mouse (ALWAYS_ALLOW stall, doctype plus body transform, wrong input window)
- **Date:** 2026-11-27
- **Error patterns:** Allow invalid certificates + Restart now does not help on WebView2, certs frame still does not load, certificate error allowed host=expired.badssl.com, main frame NavigationCompleted 10-21 s after the start, ServerCertificateErrorDetected, ALWAYS_ALLOW, video-clip black screen with Video Player = WebView2, page loaded status=200, video playing (readyState 4, currentTime advancing) but nothing painted, video rect 1920 x 0, body transform scale(1), position:fixed, <!DOCTYPE html>, standards mode vs quirks mode, url-input does not react to the mouse on WebView2, raw input registered mouse=true, input target found class=Chrome_WidgetWin_0, Chrome_WidgetWin_1, posted mouse messages never reach the page, WebGL-Fluid-Simulation draws only while dragging
- **Root cause(s):** D3: WebView2 accepted invalid certificates only through the legacy ServerCertificateErrorDetected handler (ALWAYS_ALLOW), and WebView2 holds every request allowed that way about 10 s before sending it, so with badssl.com's slow TLS the frame appeared 10-21 s after a start (CEF gets --ignore-certificate-errors and loads at network speed); D5: VideoContent.html was ported with <!DOCTYPE html> (the legacy page had none, quirks mode), so the built-in scale call (default 0, every start) put a transform on body, the transformed body became the containing block of the position:fixed video, and body is 0 px tall in standards mode, so the video was 1920 x 0 on both web engines; D6: input was posted to the first Chrome_WidgetWin_0 under the surface, WebView2's host window in Sucrose's own process, which never hands posted messages to the page (legacy GetInputHandle uses its Chrome_WidgetWin_1 child, the browser process's widget); AND the url-input page only reacts while the pointer drags, so plain moves never show anything
- **Fix:** D3 (cf8f7d6a): the WebView2 browser arguments add --ignore-certificate-errors when AllowInvalidCertificates is on (never when off, not twice), the handler stays as the legacy fallback; D5 (44758204): html,body{height:100%} in VideoContent.html, doctype kept; D6 (747bbf92): input_widget picks the Chrome_WidgetWin_1 inside the first Chrome_WidgetWin_0 (none while it is missing, else the first Chrome_WidgetWin_1); the url-input fixture description says the page draws while the pointer drags
- **Files changed:** crates/sucrose-engine-webview2/src/engine.rs, crates/sucrose-engine-webview2/src/host.rs, crates/sucrose-engine-web/src/pages/VideoContent.html, crates/sucrose-engine-web/tests/pages.rs, apps/sucrose/tests/fixtures/web-themes/url-input/SucroseInfo.json, docs/FEATURES.md, .planning/STATE.md
- **Why not caught:** no gate existed for this class: nothing measured how long an allowed bad-certificate frame takes on WebView2 (the logs only showed the handler's decision); no page test checked the layout of a ported generated page after its built-in property calls, and the doctype was added in the port without comparing with the legacy quirks-mode page; the WebView2 input target was never checked against the real window tree (window owner process) or the legacy window chain, and no run counted page-side mouse events before the 04-37 maintainer check
- **Recurrence guard:** crates/sucrose-engine-webview2/src/engine.rs engine::tests::allow_invalid_certificates_gives_webview2_the_switch_cef_gets_and_only_then; crates/sucrose-engine-web/tests/pages.rs a_page_whose_scale_property_transforms_its_body_keeps_the_body_as_tall_as_the_viewport; crates/sucrose-engine-webview2/src/host.rs host::tests::input_goes_to_the_browser_widget_inside_webview2s_host_window and host::tests::a_host_window_without_its_browser_widget_yet_is_no_target_and_the_widget_alone_is_one; KB patterns: on WebView2 accept invalid certificates with --ignore-certificate-errors like CEF, the ServerCertificateErrorDetected/ALWAYS_ALLOW path stalls each allowed request about 10 s; a <!DOCTYPE html> added to a ported legacy quirks-mode page plus a body transform collapses a position:fixed child to 0 px (add html,body{height:100%}; when a playing video shows black, measure element rects through CDP); WebView2 input must go to the Chrome_WidgetWin_1 child of Chrome_WidgetWin_0 (check window owner PIDs with a read-only FindWindowEx walk: the host window in our own process never delivers posted messages); before calling input broken, read what the test page actually reacts to (url-input only draws while dragging)

## web-loading-white-border — CEF: a light 7 px frame around the screen while a wallpaper loads (visible WS_THICKFRAME widget painted into the desktop surface)
- **Date:** 2026-11-27
- **Error patterns:** white border at the screen edges while a Web theme shows its loading screen, white frame around the screen at wallpaper start, goes away once the theme has opened, border on CEF Web, URL and YouTube wallpapers, reported on WebView2 too, no log errors, 7 px edge pixels E3E3E3 FFFFFF / B4B4B4 / A0A0A0 696969 (EDGE_RAISED + COLOR_ACTIVEBORDER), Chrome_WidgetWin_1 style 0x56050000 WS_THICKFRAME, Intermediate D3D Window 1x1 before the first frame
- **Root cause(s):** CEF's windowed browser window was created visible (cef set_as_child adds WS_VISIBLE) around Chromium's widget window Chrome_WidgetWin_1, which keeps WS_THICKFRAME (CefWindowDelegateView can resize) while removing its non-client area through WM_NCCALCSIZE; Windows painted the classic sizing frame of that child into the layered desktop surface at creation and again through DefWindowProc on later non-client messages; AND the widget never paints its client area with GDI, so the stale frame stayed until the GPU process's Intermediate D3D Window presented the page's first frame (1-3 s, longer on a cold start). Every CEF wallpaper (Web, URL, YouTube, generated pages); not WebView2 (no WS_THICKFRAME there): the WebView2 half of the 04-37 report came from the CEF YouTube wallpapers that ran between the WebView2 Web themes
- **Fix:** 6c6d9a3c: wallpaper_window_info creates the CEF browser window without WS_VISIBLE; after browser_host_create_browser_sync, show_browser_window takes WS_THICKFRAME off Chrome_WidgetWin_1 (SetWindowLongPtrW + SetWindowPos SWP_FRAMECHANGED|SWP_NOMOVE|SWP_NOSIZE|SWP_NOZORDER|SWP_NOACTIVATE), then shows the window with SW_SHOWNOACTIVATE and warns if the widget still has a non-client frame. Desktop probe: 0 framed captures in 12 CEF starts, framed again on revert; maintainer confirmed on CEF and saw no frame on WebView2
- **Files changed:** crates/sucrose-engine-cef/src/browser.rs, docs/FEATURES.md, docs/ARCHITECTURE.md
- **Why not caught:** no gate existed for this class: no test checked the window styles of the CEF browser window or of Chromium's widget under the desktop surface, and no automated run captured the desktop surface during the first seconds of a start (captures were taken after the page loaded, when the GPU window already covered the frame); the legacy CefSharp engine rendered off-screen into WPF and had no such child window to compare against; CEF themes did not get past loading before the cef-web-themes-stuck-loading fix, so the 04-37 run was the first to watch a CEF loading screen; the report named both engines because the YouTube wallpapers between the WebView2 Web themes still ran on CEF
- **Recurrence guard:** crates/sucrose-engine-cef/src/browser.rs browser::imp::tests::the_wallpaper_browser_window_is_made_hidden_as_a_child_of_the_surface, browser::imp::tests::only_the_sizing_frame_is_taken_off_a_window_style and browser::imp::tests::a_widget_without_its_sizing_frame_has_no_frame_left_to_paint; runtime warning when the widget still has a non-client frame at show time; KB patterns: a light frame at the screen edges only while a wallpaper loads is window-level, not page CSS: dump the surface's window tree (styles, owner PIDs, client vs window rect) and PrintWindow the surface and the composed Progman every 60-100 ms from the first frame, then match the edge pixels against the classic frame colours; any visible WS_THICKFRAME child under the layered desktop surface paints a sizing frame that nothing GDI repaints, so create embedded browser windows hidden and show them only after their children have lost WS_THICKFRAME; when a report names two engines, check which engine each wallpaper type actually ran on (Engine.Web, Engine.Url, Engine.YouTube are separate settings)

## youtube-player-ui-visible — YouTube wallpapers showed the player controls (title, play/pause, More videos, logo) on both web engines
- **Date:** 2026-11-27
- **Error patterns:** YouTube player UI visible, title and channel top left, play/pause icons, previous/next, More videos, YouTube logo, something at the bottom behind the taskbar, Watch on YouTube, end screen card, hideIframeElement, #movie_player, #player-controls, #bottom-sheet-wrapper, ytp-autohide, controls=0 ignored, first 5-8 s of a start, both engines, CEF and WebView2

Not the user agent (the legacy General.UserAgent gets the same layer) and not frame access (the frame is in-process and reachable on both engines since a0e22d9a)
- **Fix:** adfb0922: YouTubeContent.html hideIframeElement runs a pass at once and per mutation batch, skips a pass while #movie_player is missing (the legacy TypeError), keeps the legacy in-player rules, and SucroseHidePlayerSiblings hides every non-script sibling from #movie_player up to the body with inline display:none !important plus a data-sucrose-hidden mark that the injected Sucrose style sheet hides ([data-sucrose-hidden]{display:none !important}); captions stay (they render inside #movie_player)
- **Files changed:** crates/sucrose-engine-web/src/pages/YouTubeContent.html, crates/sucrose-engine-web/tests/pages.rs, docs/FEATURES.md

- **Recurrence guard:** crates/sucrose-engine-web/tests/pages.rs the_youtube_page_hides_the_controls_next_to_the_player_not_only_inside_it (sibling pass, mark rule, immediate pass, missing-player guard, legacy in-player rules); KB patterns: for third-party embeds, inspect the frame's whole body, not only the container the legacy script targets, and monitor every animation frame from before the frame's scripts run (Page.addScriptToEvaluateOnNewDocument) because the UI may show only for the first seconds; an inline style hide can be undone by the site's own style resets, so mark hidden elements and hide the mark from an injected style sheet; check the states in which a player shows its controls (start, resume, end, loop restart) with a positive control that lifts the hide for one synchronous scan; from WSL the CDP port of a Windows browser is reached with bun.exe, not the Linux bun

## cef-start-steals-focus — starting a CEF wallpaper took the keyboard focus and the foreground from the user's window
- **Date:** 2026-11-27
- **Error patterns:** CEF steals focus, foreground lost at wallpaper start, user's window loses focus, keystrokes go to the wallpaper until a click back, Progman foreground, Chrome_WidgetWin_1 keyboard focus, shared desktop input state, GetGUIThreadInfo, SetForegroundWindow, SetFocus, OnSetFocus, FOCUS_SOURCE_NAVIGATION, WS_EX_NOACTIVATE, ActivateBrowserOnCreation, CEF only, WebView2 unaffected
- **Root cause(s):** CEF focused and activated its widget twice while the wallpaper browser was made: CreateHostWindow -> Widget::Show without WS_EX_NOACTIVATE in the window info (SW_SHOWNORMAL, HWNDMessageHandler::Activate = SetForegroundWindow, SetInitialFocus = SetFocus), and LoadMainFrameURL -> OnSetFocus(FOCUS_SOURCE_NAVIGATION) -> ::SetFocus with no focus handler to cancel it (either is enough for the focus move); AND the surface is a child of Progman sharing explorer's desktop input state, so each call took the desktop's keyboard focus and activated Progman; AND the new renderer was allowed to set the foreground (started while its launcher was in front, or the foreground lock had expired); the port had dropped both defaults of the legacy CefSharp.Wpf.HwndHost control
- **Fix:** d860631f: wallpaper_window_info adds WS_EX_NOACTIVATE (CEF takes it off the widget after Show, so a forwarded click still focuses the page); a PageFocus focus handler with set_focus_answer cancels FOCUS_SOURCE_NAVIGATION for the wallpaper browser (System requests and popups keep CEF's default). Maintainer-confirmed 2026-11-27 (Notepad kept the foreground and its focus through a CEF start; one keydown and one keyup per press after one click on the desktop). 06421720 corrected the FEATURES.md claim that the legacy CEF engine rendered off-screen
- **Files changed:** crates/sucrose-engine-cef/src/browser.rs, docs/FEATURES.md, docs/ARCHITECTURE.md
- **Why not caught:** no gate existed for this class: no test or probe watched the foreground or the desktop focus across a wallpaper start (it was noticed only when the keyboard-input-doubled probe watched GetGUIThreadInfo); the port followed the legacy app's own code but not the defaults the CefSharp.Wpf.HwndHost control installs implicitly (its FocusHandler, ActivateBrowserOnCreation off), and docs/FEATURES.md wrongly described the legacy engine as off-screen, which hid the difference
- **Recurrence guard:** crates/sucrose-engine-cef/src/browser.rs tests browser::tests::a_page_load_never_focuses_the_wallpaper_browser (killed by the always-allow mutant) and browser::imp::tests::the_wallpaper_browser_window_is_made_hidden_and_not_activating_as_a_child_of_the_surface (killed by the no-WS_EX_NOACTIVATE mutant); docs/ARCHITECTURE.md renderer row (an engine must never activate or take the focus on its own); KB pattern: when porting from a wrapper control (CefSharp, WPF hosts), list the defaults the wrapper installs implicitly (handlers, window styles, creation flags) and port them explicitly; for an engine window under the desktop surface, watch GetForegroundWindow and GetGUIThreadInfo of Progman's thread across a start: the desktop active/focus change is the deterministic marker even when the foreground lock hides the steal; split two candidate focus paths by fixing one at a time (the handler alone did not stop the move)

## webview2-playlist-starts-at-a — YouTube playlist with Shuffle off starts at a random video when setShuffle arrives after the player's first -1 state
- **Date:** 2026-11-28
- **Error patterns:** YouTube playlist, shuffle off, random start index, startIndex not 0, intermittent, WebView2, CEF, setShuffle late, shuffleMode reads false afterwards, page call race, first -1 state, playVideoAt, no error
- **Root cause(s):** YouTubeContent.html decides a playlist's first start on the first -1 state with its legacy default `var shuffleMode = true`, while both engines send the real value with a single setShuffle from the main-frame load handler (WebView2 NavigationCompleted, CEF OnLoadEnd → ExecuteScript); the -1 state comes ~0.2 s after loadPlaylist and only 0.15-0.25 s after that call; AND-gate: the page's order-dependent default (code) AND a slower-than-usual load/host/ExecuteScript path (environment) made playVideoAt(random) run on the stale default; the legacy app has the same race via its 1 s timer
- **Fix:** the page tracks whether the engine has said the value (shuffleTold); a first -1 state before that keeps the list on its first video and marks the random start pending (shufflePending); setShuffle sets the value and makes the pending random start only when true (SucroseShuffleStart, legacy random index); legacy names, the shuffleMode global and the engine calls unchanged (D-007); commit 62ec2f49
- **Files changed:** crates/sucrose-engine-web/src/pages/YouTubeContent.html, crates/sucrose-engine-web/tests/pages.rs, docs/FEATURES.md
- **Why not caught:** no gate existed for this class: no test or probe asserted the order of an engine page call against a page event, the page was ported verbatim from the legacy page (which has the same latent race), and 04-37 had no playlist probe; CEF won the race 4 of 4 times, so a single-engine check passed
- **Recurrence guard:** regression test crates/sucrose-engine-web/tests/pages.rs:a_playlist_makes_its_random_first_start_only_once_the_engine_said_it_shuffles (red on the old page and on 3 fix-site mutants); KB pattern: when a generated page decides something on a page event using a value the engine sends by ExecuteScript after load, assume the event can come first — make the page wait for the engine's word (told flag + pending action) and prove it by fault injection (apply the engine call 400 ms late in an instrumented copy of the page); tooling lesson: after mutation testing of an include_str'd file, restore it with a fresh mtime (plain cp or touch), never cp -p, or cargo judges the dependency fresh and keeps the mutant's test artifacts (a red test on correct source text)
