Read it, never write, rename, move or delete anything there. Automated runs never turn Corrupt Themes on.
- When you start `sucrose.exe` or `sucrose-portal.exe`: set `SUCROSE_DATA_DIR="$(wslpath -w target/<scratch folder>)"` and `WSLENV=SUCROSE_DATA_DIR` (add `:SUCROSE_LOG` when you set `SUCROSE_LOG`); start the Portal with `--no-focus`; never synthesize mouse or keyboard input; capture windows only with `.claude/skills/port-feature/capture.ps1` (PrintWindow; never edit it, add no PowerShell, shell or batch script to the repository — new automation goes into `xtask`); stop what you started with `taskkill.exe /IM sucrose-portal.exe /F` and `taskkill.exe /IM sucrose.exe /F` and confirm with `tasklist.exe`. Never kill `msedgewebview2.exe` by image name: other applications use WebView2; a WebView2 renderer's browser exits with its host. Stop the apps before rebuilding (Windows locks running executables).

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-104 | Tampering | ChangeProperty | high | mitigate | The service accepts only a key that exists in the working copy with the same control type, clamps numbers to their bounds, caps text at 64 KiB, and builds the page call with `js::property_call`, which serializes the control as JSON (no string concatenation of user text into script) |
| T-04-105 | Information disclosure | D-20 import and logs | medium | mitigate | Files are copied byte for byte into the user's own data folder; values (passwordbox, API keys) are never logged (`property applied` names the key only) and never enter a SUMMARY or a commit |
