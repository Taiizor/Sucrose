## Executor environment (applies to every task)

- Run every command from the repository root in WSL. `cargo` is the Windows toolchain behind a wrapper and builds Windows binaries; never install a Linux Rust toolchain. Bun is the only JS runtime (`bun` in WSL, Windows `bun.exe` for anything that must reach a Windows 127.0.0.1 port); no node/npm/npx for project work. `python3` and `curl.exe` are fine for scratch edits and checks.
- `src/` (C#) is read-only reference: read it, never edit or build it.
- The maintainer's real data is read-only: `%APPDATA%\Sucrose` (Setting, Cache, Cache\Properties, Log, Showcase) and the library `H:\Sucrose` (reach it from WSL as `"$(wslpath -u 'H:\Sucrose')"`; never write a WSL mount path into a file). Read it, never write, rename, move or delete anything there. Automated runs never turn Corrupt Themes on.
- When you start `sucrose.exe` or `sucrose-portal.exe`: set `SUCROSE_DATA_DIR="$(wslpath -w target/<scratch folder>)"` and `WSLENV=SUCROSE_DATA_DIR` (add `:SUCROSE_LOG` when you set `SUCROSE_LOG`); start the Portal with `--no-focus`; never synthesize mouse or keyboard input; capture windows only with `.claude/skills/port-feature/capture.ps1` (PrintWindow; never edit it, add no PowerShell, shell or batch script to the repository — new automation goes into `xtask`); stop what you started with `taskkill.exe /IM sucrose-portal.exe /F` and `taskkill.exe /IM sucrose.exe /F` and confirm with `tasklist.exe`. These names match only the Rust binaries (CEF subprocesses are `sucrose.exe` too), never the C# `Sucrose.*.exe` processes. Never kill `msedgewebview2.exe` by image name: other applications use WebView2; a WebView2 renderer's browser exits with its host. Stop the apps before rebuilding (Windows locks running executables).
- Monitors: the maintainer's machine has the physical `\\.\DISPLAY1` and the intentional virtual display `\\.\DISPLAY9` (VDD by MTT). A step that needs two monitors names DISPLAY9 in its precondition; check it with the service's `monitor identified` log lines (04-40) or the `renderers started` count before you rely on it, and stop and report instead of passing a two-monitor proof on one monitor.
- Engine runs use the fixture library: `cargo xtask synth-library --out target/<folder> --count 2 --web-fixtures --media-fixtures --select <fixture> --force` writes a scratch library with prepared settings (`--engine <Type>=<legacy engine name>` sets an engine; from 04-41 `--display-mode <PerDisplay|SpanAcross|SameDuplicate>` and `--assign <device name>=<folder>` write the placement). The `video-clip` fixture holds synthetic bytes that no player decodes: a step that needs mpv to play a real video copies one Video theme's video read-only from `H:\Sucrose` over `target/<folder>/Library/video-clip/clip.mp4` first. Edit prepared settings only inside `target/`.
- CEF builds need the pinned dist (`cargo xtask fetch-engines --engine cef`; `CEF_PATH` in `.cargo/config.toml`) and CMake plus Ninja on the Windows PATH; no build downloads an engine. WebView2 needs only the user-installed WebView2 Runtime.
- Line endings: keep each file's endings. Record `git ls-files --eol <file>` for every existing file before its first edit, restore CRLF before each commit on files that were `w/crlf` (`cargo fmt` through the Windows wrapper rewrites them to LF), leave `w/lf` and new files alone, and check `git ls-files --eol` again before the commit. `docs/DECISIONS.md`, `.planning/*.md`, `apps/sucrose-portal/**`, `apps/sucrose/tests/*.rs`, `crates/sucrose-ipc/src/portal.rs`, `crates/sucrose-engine-web/**`, `crates/sucrose-engine-gif/**`, `xtask/src/*.rs` and the locale YAML files are LF; `docs/FEATURES.md` (CRLF and no newline after its last line), `docs/ARCHITECTURE.md`, `docs/MEASUREMENTS.md`, `docs/GPUI.md`, `apps/sucrose/src/*.rs`, `crates/sucrose-config/src/*.rs`, `crates/sucrose-platform/src/*.rs`, `crates/sucrose-core/src/*.rs` and `crates/sucrose-engine-mpv/src/*.rs` are CRLF in the working tree (check each with `git ls-files --eol`, this list is a guide).
- Commit messages: a subject line and a body through several `-m` flags or `git commit -F <file>`, never escaped `\n` text; check `git log -1 --format=%s` after each commit.
- `unsafe` only in `sucrose-platform`, `sucrose-sysinfo` and the engine/FFI crates; every block gets a `// SAFETY:` comment. `sucrose-engine`, `sucrose-engine-web`, `sucrose-core`, `sucrose-config`, `sucrose-ipc` and the apps stay unsafe-free.
- IPC: `ToService`, `ToRenderer`, `PortalRequest`, `PortalEvent` and `SettingChange` variants are only appended (their wire-index tests pin it); a new field in a struct inside a variant (`Assignment`, `PortalSettings`, `RuntimeState`, `EngineReportView`) bumps `PROTOCOL_VERSION` (12 at the start of Round C) or `PORTAL_PROTOCOL_VERSION` (8 at the start of Round C) by one in the same change, with the version test renamed to the new number.
- Before finishing each task: `cargo fmt --all` and the task's verify command. Before finishing the plan: `cargo xtask ci`.
