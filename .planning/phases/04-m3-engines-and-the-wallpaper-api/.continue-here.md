## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| CRLF lost to cargo fmt | `cargo fmt` through the Windows wrapper rewrites CRLF working copies to LF. Executor 04-12 committed without restoring them. | advisory | Put the line-ending orchestrator note in every executor prompt: record `git ls-files --eol` for each existing file before the first edit, restore CRLF before each commit on files that were `w/crlf`, leave `w/lf` and new files alone. 04-15..04-21 followed it. |
| Literal \n in commit messages | Executor 04-19 passed escaped newlines to git, so its four task commits carry `\n` text on the subject line (already pushed). | advisory | The orchestrator note tells executors to use several `-m` flags or `git commit -F <file>`; check `git log --format=%s` after each plan. |
| Waiting on async executors | From the REPL, `tools.Agent` returns `async_launched` at once and `Poll` returns immediately when no script runs. | advisory | Wait with a REPL script that sleeps and checks for the plan's SUMMARY plus its `docs(<plan>)` commit (under 10 min per script); completion arrives as a task-notification. |
| Unequal comparison runs | In 04-21 the C# app played the same theme during the first Rust run, and the Rust copy of the theme lacked the maintainer's per-user property values (API key, city); that run was discarded. | advisory | For Rust vs C# runs, say at every step which app must be fully closed, and copy the C# property cache file over the scratch theme's SucroseProperties.json before the Rust run (restore it after). Never commit such values. |
