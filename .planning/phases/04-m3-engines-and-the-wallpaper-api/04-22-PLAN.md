## Phase Goal

ROADMAP goal (not yet a user story; `/gsd-mvp-phase 4` can convert it, this plan does not invent one): *Every wallpaper type plays on Windows on every engine that supports it, existing web wallpapers work unchanged with the C#-compatible JavaScript API, and display modes, property editing and the performance rules match or improve on the C# app.*

**Planning round:** Round B of the five D-31 planning rounds (04-CONTEXT D-31 "Planning rounds" and its "Round B scope" bullet): D-31 slice 2 (WebView2) and slice 3 (the built-in GIF/APNG/WebP renderer, the generated pages of WAPI-08, URL, YouTube). The Round A plans 04-01..04-21 are executed and stay unchanged; Round B adds 04-22..04-38. 04-RESEARCH.md is older than 04-CONTEXT.md: where the research differs from CONTEXT (D-32..D-36, the Round B scope) or from what Round A actually built (its SUMMARYs), CONTEXT and the SUMMARYs win, and the plan says so where it matters. The Phase 3 D-17 rule ("Use disabled for non-Video themes") is lifted per type as each slice lands: the Portal card follows the service's `supported` list (`PLAYABLE` in apps/sucrose/src/service.rs), so a type becomes usable in the plan that adds it there.

This plan's slice: **WebView2 shows a Web theme** — the second web engine runs in a renderer, on the same virtual origin and resolver as CEF, chosen per type from a real runtime detection.

**Requirement status of this plan:** ENG-02 and TYPE-03 are rechecked or completed by the final checkpoint 04-37, not here.
