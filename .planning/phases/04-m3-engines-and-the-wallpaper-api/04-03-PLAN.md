## Phase Goal

ROADMAP goal (not yet a user story; `/gsd-mvp-phase 4` can convert it, this plan does not invent one): *Every wallpaper type plays on Windows on every engine that supports it, existing web wallpapers work unchanged with the C#-compatible JavaScript API, and display modes, property editing and the performance rules match or improve on the C# app.*

**Planning round:** Round A of the five D-31 planning rounds (04-CONTEXT D-31 "Planning rounds"): D-31 slice 1 only — the engine trait, detection and per-type choice with fallback, CEF bundled through `cargo xtask fetch-engines`, the virtual origin (D-14) and the JavaScript API (PropertyListener, SucroseCompatible.json, the first system data), proven with the maintainer's 8 Web themes and the fixture pages. Rounds B–E are planned after Round A has executed.

This plan's slice: **the two theme formats of the JavaScript API** — `SucroseProperties.json` and `SucroseCompatible.json` are read and written compatibly, proven with real files. Plan 09 builds the page calls on these models; plan 10 reads the data groups.

**Requirement status of this plan:** FMT-03 has no other Round A part: this plan lands it whole and marks it Complete. Complete rule: both test files pass with every real and showcase fixture and `cargo xtask ci` passes → SUMMARY `requirements-completed: [FMT-03]`; any failing fixture or an incomplete plan → `requirements-completed: []` and FMT-03 stays Pending.

## Executor environment (applies to every task)

- Run every command from the repository root in WSL. `cargo` is the Windows toolchain behind a wrapper and builds Windows binaries; never install a Linux Rust toolchain. Bun is the only JS runtime; no node/npm/npx for project work.
- `src/` (C#) is read-only reference: read it, never edit or build it.
- The maintainer's real data is read-only: `%APPDATA%\Sucrose` (Setting, Cache, Log, Showcase) and the library `H:\Sucrose` (`/mnt/h/Sucrose`). Read it, never write, rename, move or delete anything there. Automated runs never turn Corrupt Themes on.
- When you start `sucrose.exe` or `sucrose-portal.exe`: set `SUCROSE_DATA_DIR="$(wslpath -w target/<scratch folder>)"` and `WSLENV=SUCROSE_DATA_DIR` (add `:SUCROSE_LOG` when you set `SUCROSE_LOG`); start the Portal with `--no-focus`; never synthesize mouse or keyboard input; capture windows only with `.claude/skills/port-feature/capture.ps1` (PrintWindow; never edit it, add no PowerShell, shell or batch script to the repository — new automation goes into `xtask`); stop what you started with `taskkill.exe /IM sucrose-portal.exe /F` and `taskkill.exe /IM sucrose.exe /F` (CEF subprocesses are `sucrose.exe` too, so this ends them; if 04-01 took the D-32 fallback also `taskkill.exe /IM sucrose-cef.exe /F`). These names match only the Rust binaries, never the C# `Sucrose.*.exe` processes. Stop the apps before rebuilding (Windows locks running executables).
- Engine runs use the fixture library: `cargo xtask synth-library --out target/web-lib --count 2 --web-fixtures --select <fixture> --force` (from 04-01) writes `target/web-lib` with prepared settings; a scratch folder without `Setting/Sucrose.json` instead migrates the maintainer's real settings read-only and plays his selected Video theme. Edit prepared settings only inside `target/`.
- CEF builds need the pinned dist (`cargo xtask fetch-engines --engine cef`; `.cargo/config.toml` points `CEF_PATH` at it from 04-01) and CMake plus Ninja on the Windows PATH (see 04-01 user_setup). No build may download CEF.
- Line endings: keep each file's existing endings (`git ls-files --eol <file>`). `docs/DECISIONS.md`, `.planning/*.md`, `apps/sucrose-portal/**` and the locale YAML files are LF; `docs/FEATURES.md` (no newline after its last line), `docs/ARCHITECTURE.md`, `docs/MEASUREMENTS.md`, `CLAUDE.md`, `.claude/rules/*.md`, `Cargo.toml`, `.cargo/config.toml`, `deny.toml`, `xtask/engines.toml`, `.github/workflows/rust.yml` and most Rust sources outside the Portal are CRLF in the working tree.
- `unsafe` only in `sucrose-platform`, the engine/FFI crates and (from 04-10, D-34) `sucrose-sysinfo`; every block gets a `// SAFETY:` comment.
- Before finishing each task: `cargo fmt --all` and the task's verify command. Before finishing the plan: `cargo xtask ci`.
