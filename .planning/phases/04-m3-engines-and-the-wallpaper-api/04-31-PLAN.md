## Executor environment (applies to every task)

- Run every command from the repository root in WSL. `cargo` is the Windows toolchain behind a wrapper and builds Windows binaries; never install a Linux Rust toolchain. Bun is the only JS runtime; no node/npm/npx for project work.
- `src/` (C#) is read-only reference: read it, never edit or build it.
- The maintainer's real data is read-only: `%APPDATA%\Sucrose` (Setting, Cache, Log, Showcase) and the library `H:\Sucrose` (reach it from WSL as `"$(wslpath -u 'H:\Sucrose')"`; never write a WSL mount path into a committed file). Read it, never write, rename, move or delete anything there. Automated runs never turn Corrupt Themes on.
- When you start `sucrose.exe` or `sucrose-portal.exe`: set `SUCROSE_DATA_DIR="$(wslpath -w target/<scratch folder>)"` and `WSLENV=SUCROSE_DATA_DIR` (add `:SUCROSE_LOG` when you set `SUCROSE_LOG`); start the Portal with `--no-focus`; never synthesize mouse or keyboard input; capture windows only with `.claude/skills/port-feature/capture.ps1` (PrintWindow; never edit it, add no PowerShell, shell or batch script to the repository — new automation goes into `xtask`); stop what you started with `taskkill.exe /IM sucrose-portal.exe /F` and `taskkill.exe /IM sucrose.exe /F` (CEF subprocesses are `sucrose.exe` too; the `msedgewebview2.exe` processes of a WebView2 renderer exit with their host). These names match only the Rust binaries, never the C# `Sucrose.*.exe` processes. Never kill `msedgewebview2.exe` by image name: other applications on the machine use WebView2. Stop the apps before rebuilding (Windows locks running executables).
- Engine runs use the fixture library: `cargo xtask synth-library --out target/web-lib --count 2 --web-fixtures --select <fixture> --force` writes `target/web-lib` with prepared settings; from 04-23 `--engine <Type>=<legacy engine name>` (repeatable) sets the engine of a type in them, from 04-30 `--media-fixtures` adds the animation themes. A scratch folder without `Setting/Sucrose.json` instead migrates the maintainer's real settings read-only and plays his selected Video theme. Edit prepared settings only inside `target/`.
- CEF builds need the pinned dist (`cargo xtask fetch-engines --engine cef`; `CEF_PATH` in `.cargo/config.toml`) and CMake plus Ninja on the Windows PATH. No build may download an engine. WebView2 needs only the user-installed WebView2 Runtime at run time (the maintainer has 158.0.4370.33); `webview2-com-sys` links the loader statically (D-013, `.claude/rules/platform-ffi.md`).
- Line endings: keep each file's endings. Record `git ls-files --eol <file>` for every existing file before its first edit, restore CRLF before each commit on files that were `w/crlf` (`cargo fmt` through the Windows wrapper rewrites them to LF), leave `w/lf` and new files alone, and check `git ls-files --eol` again before the commit. `docs/DECISIONS.md`, `.planning/*.md`, `apps/sucrose-portal/**`, `xtask/src/measure.rs` and the locale YAML files are LF; `docs/FEATURES.md` (CRLF and no newline after its last line), `docs/ARCHITECTURE.md`, `docs/MEASUREMENTS.md`, `CLAUDE.md`, `.claude/rules/*.md`, `Cargo.toml`, `.cargo/config.toml`, `deny.toml`, `xtask/engines.toml`, `.github/workflows/rust.yml` and most Rust sources outside the Portal are CRLF in the working tree.
- Commit messages: a subject line and a body through several `-m` flags or `git commit -F <file>`, never escaped `\n` text; check `git log -1 --format=%s` after each commit.
- `unsafe` only in `sucrose-platform`, `sucrose-sysinfo` and the engine/FFI crates (Round B adds `sucrose-engine-webview2` and `sucrose-engine-gif`); every block gets a `// SAFETY:` comment and the crate keeps `#![warn(clippy::undocumented_unsafe_blocks)]`. `sucrose-engine`, `sucrose-engine-web`, `sucrose-core` and the apps stay unsafe-free.
