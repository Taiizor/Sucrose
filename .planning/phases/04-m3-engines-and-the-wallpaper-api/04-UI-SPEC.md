# Phase 04 — UI Design Contract

> Visual and interaction contract for the surfaces Phase 4 adds to the Portal (`apps/sucrose-portal`, GPUI via `gpui-kit`, D-004). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Sources: `04-CONTEXT.md` (D-01 … D-31 are locked and not re-asked), `03-UI-SPEC.md` (approved 2026-11-23; **stays in force: this file adds only what Phase 4 adds or changes**), `docs/legacy/portal.md` (Settings, DisplayPreferences, Customize rule), `docs/legacy/services.md` section 6 and `docs/legacy/engines.md` sections 3, 4 and 7 (properties editor, display modes, built-in sets), `docs/GPUI.md`, `.claude/rules/ui.md`, and the Phase 3 code (`settings/row.rs`, `toast.rs`, `banner.rs`, `dialogs/`, `library/card.rs`, `themes/sucrose.json`). Values marked "default" are researcher choices no upstream artifact fixed; the executor may tune them only against a measurement or a capture and must record the change here. The three open questions of the research pass were answered by the maintainer on 2026-11-26 and are applied below (one global certificate switch, one modal restart prompt, Phase 5 rows stay absent); no item is pending.

This is a native Rust UI: no CSS, Tailwind, shadcn or web view. "px" means GPUI logical pixels. Every user-visible string goes through rust-i18n (D-015); Phase 4 ships English only (UI-06 is Phase 5).

## Spacing Scale

Unchanged from 03-UI-SPEC (4, 8, 16, 24, 32, 48, 64; all multiples of 4). Usage added by this phase:

| Token | Value | New usage |
|-------|-------|-----------|
| xs | 4px | Gap between badge icon and number, between a control label and its help icon |
| sm | 8px | Gap between card badges, between argument row fields, between editor header buttons, between a button pair in a dialog footer |
| md | 16px | Editor window content padding and gap between property controls, gap between canvas and lists in Display Preferences, alert padding (8 x 16 as banners) |
| lg | 24px | Dialog padding, gap between sections inside Display Preferences |
| xl | 32px | Editor window title bar, icon-button hit area, Customize overlay button |
| 2xl | 48px | Monitor list row height, argument row height is 40 (exception below) |

Exceptions (all fixed sizes, not tokens):
- Display Preferences dialog width 728 px (a 680 px canvas plus 24 px padding each side); canvas 680 x 232 px (legacy 680 x 230 rounded to a multiple of 4); monitor list max height 200 px; minimum tile 48 x 28 px.
- Properties editor window width 400 px (content column 368 px), minimum height 320 px, maximum height work-area height minus 32 px, inset 16 px from the work-area edges.
- Install and confirmation dialogs 480 px (as Phase 3).
- Arguments editor row height 40 px, list body max height 240 px.
- Card badge pill height 20 px; Customize overlay button 32 x 32 px with 8 px inset from the card corner and a 28 px visible circle inside it. These fixed sizes (like the 48 x 28 px minimum monitor tile above) are component size exceptions, not spacing tokens; 28 is a multiple of 4 and is kept.
- Hairlines: 1 px borders, 2 px focus ring and selected-tile outline, 3 px selected-row indicator. Corner radius 8 px (tiles, rows, controls), 12 px (dialogs and the editor window content frame), full (pills).

## Color

Tokens and values are those of 03-UI-SPEC (dominant dark `#202020` / light `#F3F3F3`; secondary dark `#2B2B2B` / light `#FFFFFF`; accent dark `#60CDFF` / light `#005FB8`; destructive dark `#FF99A4` / light `#C42B1C`; muted text dark `#B0B0B0` / light `#5F5F5F`). The editor window and the dialogs use the same surfaces; the editor window background is the dominant color with the same backdrop and background-image layers disabled (it is opaque, so it stays readable over any wallpaper).

New role (a state signal, never an action color):

| Role | Value | Usage |
|------|-------|-------|
| Warning | Dark: background `#3A310E`, border `#7B6508`, icon `#FACC15`. Light: background `#FBF3D6`, border `#C99401`, icon `#8A6500`. The dark background and border already exist in `apps/sucrose-portal/themes/sucrose.json` (`warning.background`, `warning.border` in the dark editor-style group); the executor adds the light pair next to them in the same change and reads both modes through one helper in `theme.rs` | Persistent engine warning alert and fallback toast icon. Text stays foreground (dark `#F5F5F5`, light `#1B1B1B`). Contrast measured 2026-11-26 from the hex values (WCAG relative luminance): foreground on warning background 11.85:1 dark, 15.50:1 light; icon on warning background 8.44:1 dark, 4.79:1 light; the border is decorative (2.28:1 dark, 2.45:1 light) because icon and text carry the meaning. The component-group `warning.*` keys in that file (light yellow-500 with neutral-50, dark yellow-400 with yellow-600) are not used for this alert: neutral-50 on yellow-500 measures 1.84:1, far under 4.5:1 |

Accent reserved for (additions to the 03-UI-SPEC list, which stays):
1. The 2 px outline of the selected target monitor tile and the 3 px indicator of its row in Display Preferences (Per display mode only).
2. The selected Placement Mode radio dot.
3. The filled primary buttons added here: Save Arguments, Download and Install, Restart now, Apply Color (color picker), Close (dialogs, as before).
4. The slider fill and switch "on" state of every new control (as Phase 3).
5. The Selected pill on a card (as Phase 3; it now means "selected on the target monitor").

Accent is not used for monitor badges (neutral: black at 55% with white text, an image-overlay exception per `ui.md`), engine status text, the Customize overlay icon, or property control labels.

Destructive reserved for (additions):
1. The confirm button of "Delete Copy" in the editor (the user's customizations for that theme are removed and the wallpaper restarts).
2. The confirm button of deleting a file from a `filedropdown` (the file is removed from the theme folder).
3. Error icon and heading in the install-failure message and in new error toasts (as Phase 3).

Remove Wallpaper, Remove (argument row) and Restore Default are not destructive actions (reversible by Use, Add, or the next edit) and use outline or ghost buttons.

60/30/10 holds: the new surfaces are mostly dominant and secondary; the only accent areas are the lists above.

## Layout Contract

### Focal point per surface

Each new surface has one primary visual anchor; everything else is secondary (smaller, muted or collapsed).

| Surface | Primary anchor | Why it leads |
|---------|----------------|--------------|
| Display Preferences | The monitor canvas (680 x 232, first in the body) | It is the largest element and the only one with thumbnails; the selected tile carries the single accent outline |
| Properties editor | The control column under the theme title in the header | The title (Heading) names the wallpaper; controls are the only content and keep file order |
| Wallpaper page | The Engines and Extensions rows; an unavailable engine expands its row and shows the only Warning-colored element | The page is otherwise uniform rows, so the alert is the single deviation |
| Performance page | The Pause Rule row at the top; while a condition is active the rule banner above it | The banner is the only tinted element on the page |
| General, Sound group | The Engine Volume slider (220 px, speaker icon) | It is the only slider in the group; the checkboxes are footer sub-options |

| Interaction | Contract |
|-------------|----------|
| Use | As Phase 3, now for every supported type; applies to the target monitor (Per display) or to all (Span, Duplicate), asks nothing, and the Selected pill moves only when the service broadcasts it. A fallback engine is not an error: Use succeeds, the fallback toast and row alert appear. |
