## Phase Goal

ROADMAP goal: *An existing user's selected video theme plays behind the desktop icons on every monitor on Windows through libmpv, survives shell and monitor changes, and pauses for fullscreen apps.*

This plan's slice (UAT gap G-02-7, spike): **see on the real desktop what explorer does with its desktop window during a primary switch and an origin-only change, with the fix of 02-23/02-24 in place, and let the maintainer decide what a monitor shows while explorer leaves it outside that window.**

<objective>
Run the instrumented release build on the maintainer's desktop through UAT test 7(c) and an origin-only change, turn its logs into a timeline of placements, parent rectangles and verdicts, classify what happened, and get the maintainer's decision on the open G-02-7 item "decide what to do when explorer leaves a monitor outside Progman (spike)".

Purpose: the diagnosis inferred, but did not observe, that explorer kept Progman at layout B's rectangle for 91 s during layout C (`.planning/debug/real-screen-static-wallpaper-after-primary-switch.md`, blind_spots). After 02-23 every placement and every parent move logs Progman's rectangle and a verdict, so one run on the desktop both checks the fix and observes explorer. If explorer keeps up, the fix is complete; if it leaves a monitor outside its desktop window for long, that monitor shows the bare desktop's static wallpaper until explorer moves again, and only a different surface mode can show the video there. That choice changes user-visible behavior, so the maintainer makes it (Task 3) and 02-26 implements it. This plan writes no product code (planning rule: checkpoints and implementation go in separate plans).
Output: the spike evidence in the debug session, the decision in 02-25-SUMMARY.md.

Why no separate Progman probe: the project constraint allows the read-only probe named in the debug session only if it changes the plan. The instrumented build logs the same rectangles at every placement and parent move and exercises the fix in the same run, so a standalone probe would add nothing.
</objective>

- Run every command from the repository root in WSL. `cargo` is the Windows toolchain behind a wrapper and builds Windows binaries. Bun is the only JS runtime; no node/npm/npx.
- `src/` (C#) is read-only reference. The maintainer's real `%APPDATA%\Sucrose` is read-only: the run uses `SUCROSE_DATA_DIR` = target/scratch-data (with `WSLENV`).

- The debug session file uses LF line endings: keep LF.
