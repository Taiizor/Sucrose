**WR-19 judgment.** The defect is real but narrow. It needs a renderer to send `Failed` and the service to handle that renderer's exit first while its slot is being released (unplug or fullscreen Close), which is the same millisecond two-thread ordering WR-18 described. The only effect is the single global tray status/tooltip text; it does not stop or restart any renderer, does not touch the election, `playing` set, budgets or Quit, and the other monitors keep playing. SC2 says the wallpaper survives monitor plug/unplug (playback and recovery), not what the tooltip says; TRAY-01 is "a tray icon with Quit is available while a wallpaper runs", which this path does not affect. The log still carries the reason. It does not block a phase truth or success criterion, so it is an advisory, not a gap. It is worth the small fix (a `slot_assigned` argument and one test) before M2 builds on the status path, and the UAT 7 unplug check should include a glance at the tooltip.
