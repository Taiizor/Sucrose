## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-53 | Spoofing | surface.rs fallback window ("fallback" only) | low | mitigate | The fallback window is a WS_EX_TOOLWINDOW, WS_EX_NOACTIVATE window that answers MA_NOACTIVATE and is pinned to HWND_BOTTOM in WM_WINDOWPOSCHANGING, so it never takes the focus, never shows in the taskbar or Alt-Tab and never covers an application window; it exists only while explorer's desktop window does not overlap its monitor, so it never covers explorer's icons |
| T-02-54 | Denial of Service | surface.rs detach and reattach ("fallback" only) | low | mitigate | Switches are driven only by set_rect and the location watch, which re-places only when the parent rectangle changed; detach needs no overlap and reattach any overlap, so one parent rectangle cannot make the surface toggle, and a failed reattach falls back to the fallback window until the next parent change |
| T-02-55 | Denial of Service | surface.rs location watch (class c only) | low | mitigate | Widened to explorer's process, the callback still returns after an O(1) comparison of the event window and object id for every event that is not the watched parent or root; nothing else runs for them |
| T-02-SC | Tampering | crates.io dependencies | high | mitigate | No crate and no windows feature is added (HWND_BOTTOM, WM_WINDOWPOSCHANGING and WINDOWPOS are in the enabled Win32_UI_WindowsAndMessaging); `cargo deny check` runs in CI |
