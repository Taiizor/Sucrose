# Phase 2 Plan 04: Legacy M1 settings Summary

**Every D-09 key of the C# install is read read-only with legacy defaults, clamps and parsing quirks, and the service logs the values it will use (volume 100, UniformToFill, fullscreen Resume on the maintainer's machine).**

## Performance

- **Duration:** 7 min
- **Tasks:** 2
- **Files modified:** 13

## Accomplishments
- `sucrose_core::settings` holds Stretch, ScreenArea, FullScreenAction and PauseKind with the legacy defaults and exact, case-sensitive names; ordinals exist only for the three enums whose order formats.md documents.
- `Properties` got typed getters (`get_bool`, `get_i64` accepting numeric strings, `get_clamped`, `get_enum`) and `LegacySettings::load` fills the four-file snapshot. DisplayScreenType, ScreenDevice, CrashExplorer, the Video engine choice and StayAwake are not read.
- The service start logs one `legacy settings` line with values only. Real run on the maintainer's machine: `volume=100 looping=true stretch=UniformToFill hardware_acceleration=true screen=DisplayBound fullscreen=Resume pause=Light app_visible=true`, no invalid-setting warnings, and the real Setting files' modification times were unchanged.
- Seven sanitized fixtures (real key sets, no profile paths) and 16 integration tests, including a guard that fails on any user profile path in a fixture.

## Decisions Made
- Out-of-range numbers are clamped rather than defaulted (the behavior list is explicit: 250 gives 100, -5 gives 0); other bad values give the default. Both log a warning naming the file and key.
- The retry in `read` (plan 03) already covers sharing violations (raw OS error 32), other transient I/O errors and empty files; Task 2 only added a unit test pinning that classification.
