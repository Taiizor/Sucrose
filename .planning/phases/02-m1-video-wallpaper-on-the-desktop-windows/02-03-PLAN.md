## Phase Goal

ROADMAP goal (not yet a user story; `/gsd-mvp-phase 2` can convert it): *An existing user's selected video theme plays behind the desktop icons on every monitor on Windows through libmpv, survives shell and monitor changes, and pauses for fullscreen apps.*

This plan's slice: **Sucrose finds the theme the user selected in the C# app** — the service reads the real legacy `Library.json` and the theme's `SucroseInfo.json` and logs what it would play. This is the tracer of the legacy-reader path; plan 04 completes every M1 setting with legacy defaults and fixtures.

<objective>
Create `sucrose-config` with the core of the read-only legacy reader (FMT-08) and the first part of the theme model in `sucrose-core`, wired into the service start as one path end to end: real `Library.json` → `LibrarySettings` → `SucroseInfo.json` → a service log line.

Purpose: FMT-08 and the TYPE-01 path start here; FMT-01 (Phase 3) reuses this reader for migration (D-09 "build the reader so FMT-01 can reuse it"). Plan 04 builds the D-09 key set and its fixture tests on this reader.
Output: `crates/sucrose-config` (`LegacyFile`, `Properties`, `read`, `LibrarySettings`), `sucrose_core::{paths::legacy_*, theme}`, a service log line naming the selected theme.
</objective>

Legacy format (docs/legacy/formats.md §1.1, §1.3): files `%APPDATA%\Sucrose\Setting\<File>.json` = `{"Properties": {...}}`, 2-space indent, CRLF, UTF-8 without BOM (reader must tolerate one); enums are name strings (case-sensitive; numeric strings accepted by Enum.Parse); ints are JSON numbers; any read error → default. The C# writer truncates in place with FileShare.None (not atomic), so a read may hit a sharing violation or an empty file.

## Executor environment (applies to every task)

- Run every command from the repository root in WSL. `cargo` is the Windows toolchain behind a wrapper and builds Windows binaries; never install a Linux Rust toolchain. Bun is the only JS runtime; no node/npm/npx.
- `src/` (C#) is read-only reference: never edit or build it. Copying a file out of it is allowed where a task says so.
- The maintainer's real `%APPDATA%\Sucrose` (Setting, Library, Cache) is read-only. Read it, never write, rename or delete anything in it.
- When you start `sucrose.exe`: close nothing of the C# app yourself (D-07); set `SUCROSE_DATA_DIR="$(wslpath -w target/scratch-data)"` and `WSLENV=SUCROSE_DATA_DIR`; never synthesize mouse or keyboard input; stop what you started with `taskkill.exe /IM sucrose.exe /F` (this matches only the Rust binary, never `Sucrose.*.exe` C# processes); stop the app before rebuilding (Windows locks running executables).
- Preserve each file's line endings (`.planning/` and `docs/` files are LF in the working tree; check before editing).
- Before finishing each task: `cargo fmt --all`, and the task's verify command. Before finishing the plan: `cargo xtask ci`.
