## Phase Goal

ROADMAP goal (not yet a user story; `/gsd-mvp-phase 2` can convert it): *An existing user's selected video theme plays behind the desktop icons on every monitor on Windows through libmpv, survives shell and monitor changes, and pauses for fullscreen apps.*

This plan's slice (verification advisory WR-19, "worth fixing in the same pass"): **after a monitor is unplugged, or the fullscreen rule closes a renderer, a late failure of that renderer no longer makes the tray say "no wallpaper" while the other monitors play.**

<objective>
Make `handle_report` in `apps/sucrose/src/service.rs` drop a report whose slot no longer belongs to a connected monitor or whose renderer the fullscreen rule closed, through a new `SlotState` argument (link pid, running processes, assigned flag) and a new `Fleet::slot_assigned`; cover it with unit tests; then make the parity record and the service's doc comments say what the code does (FEATURES row 'Video', IN-25; IN-28 service part).

Purpose: WR-19 (02-REVIEW.md, open in 02-REVIEW-DISPOSITION.md): the WR-18 fix keeps a late `Failed` of a renderer that ended with nobody replacing it, but it does not know whether the slot still belongs to a monitor. When a monitor is unplugged (service sends Close, the `Exited` arm takes the `fleet.slots.release` branch and `continue`s) or the fullscreen rule closed the renderer (`rule_closed.note_exit` branch), a `Failed` queued behind that exit is kept and the single global status reads "no wallpaper: ..." while the other monitors play, until some renderer reports `Playing`.
Output: the fix and its tests in service.rs, the FEATURES 'Video' row wording, current doc comments.

Gap status: WR-19 is a review advisory with no UAT id, so this plan lists no gap_ids. It does not touch G-02-7 or 02-UAT.md.
</objective>
