## Phase Goal

ROADMAP goal: *An existing user's selected video theme plays behind the desktop icons on every monitor on Windows through libmpv, survives shell and monitor changes, and pauses for fullscreen apps.*

This plan's slice (UAT gap G-02-2b, and the root cause of G-02-6): **the video plays smoothly on a hybrid-GPU laptop because Sucrose asks Windows for the high-performance GPU, exactly as the C# app does.** The maintainer decided in UAT (test 6, option 1) to pull DESK-12 ("GPU preference (high performance)", planned for Phase 5) into this gap closure; the planner moved DESK-12 to Phase 2 in ROADMAP.md and REQUIREMENTS.md when these plans were written.

<objective>
Port the legacy GPU preference (SSDHG.Configure / GraphicPreference.EnsureHighPerformance): read Engine.json GraphicPreference, write UserGpuPreferences for sucrose.exe before any renderer starts, and log the adapter each renderer's Direct3D device uses.

Purpose: without it libmpv's D3D11 device lands on DXGI adapter 0, which is the Intel UHD whenever the internal panel is primary; that GPU cannot render the 4K60 HEVC theme (98 % 3D, A/V desync, about 0.28x playback). Root cause: `.planning/debug/renderer-runs-on-power-saving-gpu.md`.
Output: `sucrose-platform` GPU module and capability, `GpuPreference` setting, service and renderer wiring, docs.

Not in this plan (open maintainer decision, not parity): passing mpv `d3d11-adapter` chosen through EnumAdapterByGpuPreference so the GPU no longer depends on which display is primary. Do not add it; it is listed under "Open decisions" below.
</objective>

Legacy behavior (src/Shared/Sucrose.Shared.Space/Extension/GraphicPreference.cs, read-only reference):
- Key HKCU\Software\Microsoft\DirectX\UserGpuPreferences (created when missing); value name = the exe's full path; type REG_SZ; data "Key=Value;Key=Value;" with a trailing ';'.
- Parse: split on ';' dropping empty parts, trim each part, split at the first '='; keep a pair only when key and value are both non-empty; keys compare case-insensitively (a later duplicate overwrites the earlier value but keeps its position and spelling).
- Current preference = the GpuPreference pair parsed as an integer that is 0, 1 or 2; anything else (missing, not a number, out of range) counts as Default (0). When it equals the wanted ordinal nothing is written (so Default with no value writes nothing).
- Otherwise set GpuPreference (existing key spelling kept, else appended as "GpuPreference") and write all pairs back joined with ';' plus a trailing ';'. A non-string value counts as missing.
- Engine.json key GraphicPreference, enum HighPerformanceType { Default, PowerSaving, HighPerformance } (docs/legacy/formats.md §1.3 and the enum list), default HighPerformance; the registry number is the enum ordinal.

Existing Rust facts:

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
