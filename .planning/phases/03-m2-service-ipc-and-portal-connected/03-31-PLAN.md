## Phase Goal

ROADMAP goal (not yet a user story; `/gsd-mvp-phase 3` can convert it, this plan does not invent one): *The service and the Portal work as one app: the user picks a theme in the Portal's library, "Use" applies it through the service, settings migrate from the C# install and persist, and Sucrose can start with the OS.*

This gap-closure plan's slice: **the user can move the library** (SC1, LIB-09) without other service work interfering, and the tray never shows forged text (review WR-01, WR-03, WR-07).

<objective>
Fix three review warnings around the library move in `apps/sucrose/src/service.rs`: maintenance is accepted while a move runs (WR-01), the move does not fully quiesce the fleet (a settled monitor snapshot is thrown away; a queued respawn can reopen the old folder, WR-03), and a `Status::NoWallpaper` reason built from `Library.Selected` reaches the log and tooltip without `printable()` (WR-07). Each fix gets a unit test.

Purpose: LIB-09 robustness; review warnings WR-01, WR-03, WR-07 end as fixed.
Output: service.rs changes and tests.
</objective>
