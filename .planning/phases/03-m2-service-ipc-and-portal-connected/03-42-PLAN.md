## Phase Goal

ROADMAP goal (not yet a user story; `/gsd-mvp-phase 3` can convert it, this plan does not invent one): *The service and the Portal work as one app: the user picks a theme in the Portal's library, "Use" applies it through the service, settings migrate from the C# install and persist, and Sucrose can start with the OS.*

This gap-closure plan's slice: **the user can page and scroll through the library and see every thumbnail and hover preview** (SC1, SC5; LIB-04, LIB-06, UI-07; UAT tests 6 and 8, gaps G-03-6 and G-03-8): thumbnails follow the scroll position instead of stopping at the 64th card, and the grid shows its scrollbar.

<objective>
Request thumbnails for the rows in view (plus one row ahead) as the grid scrolls, keep wanted thumbnails in the bounded cache, show a scrollbar on the grid, and stop the animated placeholder on cards that are not loading.

Purpose: G-03-6 and G-03-8. root_cause (binding): (1) the grid scrolls with `overflow_y_scroll()` and draws no scrollbar; (2) `request_page()` queues only the first CACHE_IMAGES (64) cards of the page (since 03-10, e5d7d870), so with 100 per page cards 65-90 are never requested and stay skeletons; `cards()` reorders the cache on every render and evicted keys that are on screen again are never requested; CACHE_IMAGES 64 and CACHE_BYTES 48 MiB (about 41 images at W720) mean that removing the cap alone would evict card 1 when card 65 arrives and never reload it. (3) The missing hover preview is the maintainer's LibraryPreview=false setting, not a code defect; 03-43 re-runs it with the preview on.
Output: layout and cache functions with tests, the in-view request in LibraryView, the scrollbar, the static placeholder, a first-screen release log, GPUI.md and FEATURES.md notes. The D-25 measurement of this path is 03-44 (test 10).
</objective>
