## Phase Goal

ROADMAP goal (not yet a user story; `/gsd-mvp-phase 3` can convert it, this plan does not invent one): *The service and the Portal work as one app: the user picks a theme in the Portal's library, "Use" applies it through the service, settings migrate from the C# install and persist, and Sucrose can start with the OS.*

This gap-closure plan's slice: **Exit closes every Sucrose process** (SC3, TRAY-05) without cutting a library move in half, and a Portal cannot change anything once the service is closing (review WR-02).

<objective>
Fix WR-02: `quitting` is checked for tray Open, Launch and the timers but not for `Event::Portal`, so after Close Applications the Portal can still start a move (`MoveEnv::start` ignores `quitting`), write `Library.Selected` through Use, or change settings; and `ShutdownDone` / `Closing::done` return `Flow::Exit` while the library-ops worker may be mid-copy. Gate state-changing Portal requests while quitting and hold the exit while a move runs.

Purpose: TRAY-05 (truth 6 of 03-VERIFICATION, behavior-unverified) and ARCH-05; review WR-02 ends as fixed.
Output: service.rs changes and tests.
</objective>
