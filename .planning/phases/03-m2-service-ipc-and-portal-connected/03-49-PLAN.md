## Executor environment (applies to every task)

- Run every command from the repository root in WSL. `cargo` is the Windows toolchain behind a wrapper and builds Windows binaries; never install a Linux Rust toolchain. Bun is the only JS runtime; no node/npm/npx.
- `src/` (C#) is read-only reference: never edit or build it. Never edit the executed plans 03-01..03-44 or their SUMMARY files (03-44's halted SUMMARY stays as it is).
- The maintainer's real data is read-only: `%APPDATA%\Sucrose` (Setting, Cache, Log, Showcase) and the library folder its settings name. Read it; never write, rename, move, trash or delete anything there.
- When you start `sucrose.exe` or `sucrose-portal.exe`: set `SUCROSE_DATA_DIR="$(wslpath -w target/<scratch folder>)"` with `WSLENV=SUCROSE_DATA_DIR` (`WSLENV=SUCROSE_DATA_DIR:SUCROSE_LOG` when a log filter is set); start the Portal with `--no-focus` unless the maintainer drives it; never synthesize mouse or keyboard input; stop what you started with `taskkill.exe /IM sucrose-portal.exe /F` and `taskkill.exe /IM sucrose.exe /F` (they match only the Rust binaries, never the C# `Sucrose.*.exe` processes) and confirm with `tasklist.exe`; stop the apps before rebuilding (Windows locks running executables).
- Window captures: `.claude/skills/port-feature/capture.ps1` (PrintWindow) works only with Backdrop None and returns no content under a backdrop; a backdrop is judged only by the maintainer's eye on the active window. Add no PowerShell, shell or batch script to the repository (automation goes into `xtask`).
- Every scratch `Setting/Sucrose.json` a task prepares must hold `"DeleteCorrupt": false` before any Rust Sucrose process starts on it (the service would otherwise move corrupt themes to the Recycle Bin).
- Line endings: keep each file's working-tree endings (`git ls-files --eol <file>` before editing). LF: `.planning/*.md`, `Cargo.lock`, `apps/sucrose-portal/src/app.rs`, `theme.rs`, `main.rs`, `library/mod.rs`, `library/layout.rs`, `library/card.rs`, `docs/DECISIONS.md`. If `git status` shows untouched files as modified with an empty diff, it is a line-ending artifact: never commit or "fix" it on its own.
- Before finishing each task: `cargo fmt --all` and the task's verify command. Before finishing the plan: `cargo xtask ci` (fmt, clippy, tests).
- Requirement status: the executor's update step marks this plan's `requirements` Complete only once every plan of the phase that declares an ID has a SUMMARY, and never on a halted or skipped plan.
- Parallel execution is off (`.planning/config.json` `parallelization: false`). If an orchestrator still runs a plan in a worktree that shares `target/`, re-run the plan's tests in the main checkout afterwards (`cargo clean -p <member>` when paths are stale).
