## Executor environment (applies to every task)

- Run every command from the repository root in WSL. `cargo` is the Windows toolchain behind a wrapper and builds Windows binaries; never install a Linux Rust toolchain. Bun is the only JS runtime; no node/npm/npx.
- `src/` (C#) is read-only reference: never edit or build it. Never edit the executed plans 03-01..03-40 or their SUMMARY files.
- The maintainer's real data is read-only: `%APPDATA%\Sucrose` (Setting, Cache, Log, Showcase) and the library folder its settings name. Read it; never write, rename, move, trash or delete anything there.
- When you start `sucrose.exe` or `sucrose-portal.exe`: set `SUCROSE_DATA_DIR="$(wslpath -w target/<scratch folder>)"` with `WSLENV=SUCROSE_DATA_DIR` (`WSLENV=SUCROSE_DATA_DIR:SUCROSE_LOG` when a log filter is set); start the Portal with `--no-focus` unless the maintainer uses it; never synthesize mouse or keyboard input; stop what you started with `taskkill.exe /IM sucrose-portal.exe /F` and `taskkill.exe /IM sucrose.exe /F` (they match only the Rust binaries, never the C# `Sucrose.*.exe` processes) and confirm with `tasklist.exe`; stop the apps before rebuilding (Windows locks running executables).
- Window captures: `.claude/skills/port-feature/capture.ps1` (PrintWindow) works only with Backdrop None; PrintWindow returns no content for a window with the Acrylic backdrop (debug session portal-backdrop-no-visible-effect). Add no PowerShell, shell or batch script to the repository (automation goes into `xtask`); a throwaway helper the executor writes under `target/` (gitignored, never committed) is allowed where a task says so.
- Every scratch `Setting/Sucrose.json` a task prepares must hold `"DeleteCorrupt": false` before any Rust Sucrose process starts on it (the service would otherwise move corrupt themes to the Recycle Bin).
- Line endings: keep each file's working-tree endings (`git ls-files --eol <file>` before editing). LF: `.planning/*.md`, `apps/sucrose-portal/src/app.rs`, `theme.rs`, `main.rs`, `library/mod.rs`, `library/layout.rs`, `library/card.rs`, `docs/DECISIONS.md`. CRLF: `apps/sucrose-portal/src/library/grid.rs`, `apps/sucrose-portal/src/library/thumbs.rs`, `docs/GPUI.md`, `docs/FEATURES.md` (no final newline), `docs/MEASUREMENTS.md`. If `git status` shows untouched files as modified with an empty diff, it is a line-ending artifact: never commit or "fix" it on its own.
- Before finishing each task: `cargo fmt --all` and the task's verify command. Before finishing the plan: `cargo xtask ci` (fmt, clippy, tests).
- Requirement status: the executor's update step marks this plan's `requirements` Complete only once every plan of the phase that declares an ID has a SUMMARY.
- Talk to the maintainer in Turkish (their global rule); plans, code, comments, docs and commit messages stay in English.

## Run rules (binding)

- Prepare everything first (release build, scratch data, commands), and only then present the checkpoint; nothing the maintainer has to watch runs before they reply.
- Visual checks on DISPLAY1 (DISPLAY9 is an intentional virtual display; two renderers are expected when a wallpaper plays).
- Focus: the unattended smoke pass starts the Portal without focus (`--no-focus`); the run the maintainer drives starts it WITH focus. CLAUDE.md (Environment) scopes no-focus to automated checks: "For automated checks start it without focus (`--no-focus` in the prototype), capture with `PrintWindow`, never synthesize mouse or keyboard input, and close what you started." A run the maintainer drives by hand is not an automated check, so the window gets focus; no input is synthesized; the executor only starts the apps, reads the logs and stops what it started.
- Stop every app you started (`taskkill.exe /IM sucrose-portal.exe /F`, `taskkill.exe /IM sucrose.exe /F`) and confirm with `tasklist.exe`.
