## Phase Goal

ROADMAP goal (not yet a user story; `/gsd-mvp-phase 3` can convert it, this plan does not invent one): *The service and the Portal work as one app: the user picks a theme in the Portal's library, "Use" applies it through the service, settings migrate from the C# install and persist, and Sucrose can start with the OS.*

This gap-closure plan's slice: **the user sees a scrollbar on the library grid that stays on its right edge, and the cards in view keep getting their thumbnails after the window or the page changes size** (SC1 paging, LIB-04, UI-07; truth 17 of 03-VERIFICATION.md, UAT gap G-03-6, review findings WR-15 and WR-16, the WR-16 edge of truth 4): the bar is mounted beside the scroll area instead of inside it, and the rows in view are computed from a clamped offset and settled on the next frame.

<objective>
Fix WR-15 in code: mount the grid's vertical scrollbar as a sibling of the scroll area inside a non-scrolling relative wrapper, prove with GPUI layout tests that it stays on the right edge while the cards scroll and does not block the cards, check the release Portal still requests the first screen's thumbnails, and correct docs/GPUI.md and docs/FEATURES.md. Fix WR-16 in the same scroll area: clamp the offset the view reads in render to the content of the rows it requests, and render once more on the next frame when the painted bounds or offset differ from what render read, proven by layout and GPUI tests.

Purpose: the maintainer saw no scrollbar (03-43). `vertical_scrollbar(scroll)` appends its overlay inside the element that scrolls, and GPUI offsets every child of a scroll container, absolute ones included, so the bar moved away with the content; on Windows the OS-synced mode is also hover-only while the OS auto-hides scrollbars. WR-16: the request reads the handle's offset and bounds from the previous frame and GPUI clamps the offset only after render, so after a content shrink or a taller window the visible cards stayed on the static Idle fill, which asks for no frame. The visibility on the desktop (and the cards after a resize) is judged by the maintainer in 03-47; the memory rerun on this final path is 03-50, which runs after this plan.
Output: grid::scroll_area with the sibling overlay and three GPUI tests; grid::visible_rows with layout::clamped_scroll_top, two layout tests and two GPUI tests; GPUI.md and FEATURES.md updated.
</objective>
