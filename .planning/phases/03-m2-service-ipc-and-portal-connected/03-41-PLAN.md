## Phase Goal

ROADMAP goal (not yet a user story; `/gsd-mvp-phase 3` can convert it, this plan does not invent one): *The service and the Portal work as one app: the user picks a theme in the Portal's library, "Use" applies it through the service, settings migrate from the C# install and persist, and Sucrose can start with the OS.*

This gap-closure plan's slice: **the Portal follows light or dark with its Mica/Acrylic backdrop** (SC5, UI-01, UI-02; UAT test 5 step 2, gap G-03-5): the backdrop the window already requests becomes visible because the opaque layer under the Portal view is cleared while a backdrop is active.

<objective>
Make the stored window backdrop visible: clear the opaque fill that gpui-component's Root plugin paints under the Portal view while a backdrop is active (and keep it for Backdrop None), apply it at open (deferred until the Root exists), on Welcome and on Changed(Backdrop), prove it on the release build with a real screen copy (None against Acrylic), and record the GPUI lesson.

Purpose: G-03-5. root_cause (binding): gpui_kit::open_window wraps the Portal view in gpui_base::Root, whose gpui-component RootPlugin::style paints `.bg(tokens.background)`, opaque #202020 (Dark) / #F3F3F3 (Light); plan 03-17 lowered the alpha only on the Portal's own page div (theme::page_alpha 0.78), so Acrylic, Mica, Tabbed and None produce the same pixels. A probe with the same gpui-kit 0.10.0 open path showed a blurred desktop once only the Root background was transparent.
Output: theme.rs root fill functions and tests, app.rs wiring, a measured None/Acrylic screen comparison in the SUMMARY, docs/GPUI.md lesson. The maintainer's eye check of Acrylic, Mica, Tabbed and None on the active window is plan 03-43.
</objective>
