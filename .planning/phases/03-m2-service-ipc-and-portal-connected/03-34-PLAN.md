## Phase Goal

ROADMAP goal (not yet a user story; `/gsd-mvp-phase 3` can convert it, this plan does not invent one): *The service and the Portal work as one app: the user picks a theme in the Portal's library, "Use" applies it through the service, settings migrate from the C# install and persist, and Sucrose can start with the OS.*

This gap-closure plan's slice: **"Use" applies the wallpaper through the service** (ARCH-05) and the renderer reports the new theme as playing only when it really plays (review WR-08).

<objective>
Fix WR-08: `load_source` sets one `loading` boolean and the event thread takes the next `PLAYBACK_RESTART` as the new file's first frame. A restart of the old file already queued in mpv (frequent for a short looping wallpaper) is consumed by that branch: `has_started` turns true with the old frame, the clock announces Playing early and the follower anchors on the old position. Tie the start to the file-loaded event of the requested file.

Purpose: ARCH-01 / ARCH-05 correctness of the D-26 LoadSource transition; review WR-08 ends as fixed.
Output: a pure `SourceSwitch` in player.rs, wired into the event loop, with sequence tests.
</objective>
