## Phase Goal

ROADMAP goal (not yet a user story; `/gsd-mvp-phase 3` can convert it, this plan does not invent one): *The service and the Portal work as one app: the user picks a theme in the Portal's library, "Use" applies it through the service, settings migrate from the C# install and persist, and Sucrose can start with the OS.*

This gap-closure plan's slice: **the user sees hover previews in the library** (SC1, LIB-06, 03-VERIFICATION gap 1): a hovered card animates instead of showing frame 0.

<objective>
Make the hover preview animate: give the preview `img()` in `render_card` a stable element id, prove with a GPUI test that a second frame is painted, make every silent return of the hover path visible at debug level, and have the maintainer confirm on the release Portal.

Purpose: LIB-06 / SC1 gap 1. Depends on 03-27, because an animating preview puts every frame into the atlas and those frames must leave it when the hover ends.
Output: card.rs id and test, hover diagnostics, GPUI.md and FEATURES.md notes, the maintainer's hover verdict in the SUMMARY.

Checked while planning (2026-11-24): the maintainer's Windows has "Animation effects" on (`SystemParametersInfoW(SPI_GETCLIENTAREAANIMATION)` returned true), so gpui-base sets `App::reduce_motion` false and GPUI's img animation is not switched off by the OS on this machine.
</objective>
