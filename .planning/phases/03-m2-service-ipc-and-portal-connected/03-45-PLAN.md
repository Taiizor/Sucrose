## Phase Goal

ROADMAP goal (not yet a user story; `/gsd-mvp-phase 3` can convert it, this plan does not invent one): *The service and the Portal work as one app: the user picks a theme in the Portal's library, "Use" applies it through the service, settings migrate from the C# install and persist, and Sucrose can start with the OS.*

This gap-closure plan's slice: **choosing Mica or Tabbed in the Portal's settings reaches the window** (SC5, UI-01, UI-02; gap "SC5 backdrop" of 03-VERIFICATION.md, review finding WR-14): the earlier Acrylic is cleared before another material is applied, the DWM system backdrop type is set and reset by Sucrose itself, and the log says what the OS answered.

<objective>
Fix WR-14 in code: apply Opaque before every changed window appearance, set DWMWA_SYSTEMBACKDROP_TYPE (none, main, tabbed) through a new safe sucrose-platform call that returns the HRESULT, log that result, and correct docs/GPUI.md and docs/ARCHITECTURE.md to the mechanism.

Purpose: the maintainer saw Acrylic and None work while Mica and Tabbed changed nothing (03-43). gpui-pre-windows 0.3.12 drives Acrylic and Opaque through the accent policy and Mica/Tabbed only through DwmSetWindowAttribute, never clearing one when it sets the other, and drops the HRESULT. The visual result is judged by the maintainer in 03-47, not here.
Output: Platform::set_window_backdrop (Windows implementation, Unsupported elsewhere), theme::appearance_steps, apply_backdrop with steps and dwm_result in its log line, GPUI.md and ARCHITECTURE.md updated.
</objective>
