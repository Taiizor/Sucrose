## Phase Goal

ROADMAP goal (not yet a user story; `/gsd-mvp-phase 3` can convert it, this plan does not invent one): *The service and the Portal work as one app: the user picks a theme in the Portal's library, "Use" applies it through the service, settings migrate from the C# install and persist, and Sucrose can start with the OS.*

This gap-closure plan's slice: **settings persist** (SC2, ARCH-04, 03-VERIFICATION gap 4, review CR-02): a transient read error never rolls the user's settings back.

<objective>
Close CR-02: `read_file` maps every I/O error except not-found to `Read::Corrupt`, so a sharing violation, an antivirus scan or an access-denied while another process holds `Sucrose.json` makes `Store::open` restore the older `.bak` over it or migrate and persist over it. Separate Unreadable from Corrupt, retry the read, and return `Err(StoreError::Io)` (the host's in-memory no-save mode) instead of restoring or migrating; prove with a locked-file test that nothing is overwritten.

Purpose: CR-02 / gap 4; ARCH-04 goes from PARTIAL to satisfied.
Output: store.rs changes and store tests.
</objective>
