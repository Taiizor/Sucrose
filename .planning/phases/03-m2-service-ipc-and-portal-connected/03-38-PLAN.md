## Run rules (binding, lessons of 03-11 and 03-24)

- Prepare everything first (release build, scratch data, commands), do NOT start the clock, return the ready checkpoint. The run starts only after the maintainer replies "start".
- On "start", the continuation starts the Portal and the sampler at once (lead about 30 s while the library loads), then returns the exact local start time and the cue at once.
- The maintainer pages at their own pace; the rounds are read from the Portal's page log, so nothing depends on clock alignment. The maintainer ends the run by closing the Portal window after at least 30 s idle on page 1.
- Visual checks on DISPLAY1 (DISPLAY9 is an intentional virtual display; two renderers are expected when a wallpaper plays).
- Focus: the unattended smoke pass of Task 1 starts the Portal without focus (`--no-focus`); the timed run of Task 3 starts it WITH focus. CLAUDE.md (Environment) scopes no-focus to automated checks: "For automated checks start it without focus (`--no-focus` in the prototype), capture with `PrintWindow`, never synthesize mouse or keyboard input, and close what you started." The timed run is not an automated check: the maintainer pages and hovers by hand in the window, so it gets focus. No input is synthesized; the executor only starts the apps, samples, reads the log and stops what it started.
- Stop every app you started (`taskkill.exe /IM sucrose-portal.exe /F`, `taskkill.exe /IM sucrose.exe /F`) and confirm with `tasklist.exe`.
