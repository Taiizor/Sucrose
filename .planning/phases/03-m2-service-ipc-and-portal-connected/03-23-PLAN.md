## Phase Goal

ROADMAP goal (not yet a user story; `/gsd-mvp-phase 3` can convert it, this plan does not invent one): *The service and the Portal work as one app: the user picks a theme in the Portal's library, "Use" applies it through the service, settings migrate from the C# install and persist, and Sucrose can start with the OS.*

This plan's slice: **Sucrose can start with the OS** — the user turns on normal startup in the Portal, Sucrose writes its own entry next to the C# one without touching it, and after sign-in the wallpaper comes back.

<objective>
Implement normal startup on all three OSes in `sucrose-platform` (Run value, LaunchAgent, XDG autostart) with pure, tested text builders, legacy entry detection on Windows, the service's `SetStartup` and `RefreshStartup` handling, the Portal row with its notes, and D-034 for the entry name the Phase 5 updater and uninstaller must find.

Purpose: TRAY-03 (success criterion 4), D-08.
Output: `crates/sucrose-platform/src/autostart.rs` (+ Windows part), service handling, the Startup row, D-034.
</objective>

## Executor environment (applies to every task)

- Run every command from the repository root in WSL. `cargo` is the Windows toolchain behind a wrapper and builds Windows binaries; never install a Linux Rust toolchain. Bun is the only JS runtime; no node/npm/npx.
- `src/` (C#) is read-only reference: never edit or build it.
- The maintainer's real data is read-only: `%APPDATA%\Sucrose` (Setting, Cache, Log, Showcase) and the library folder its legacy `Library.json` names. Read it, never write, rename, move, trash or delete anything there. Automated runs never turn Corrupt Themes on and never move the library while the library location is the real one; those behaviors run on temporary trees and on `cargo xtask synth-library` output only.
- When you start `sucrose.exe` or `sucrose-portal.exe`: set `SUCROSE_DATA_DIR="$(wslpath -w target/<scratch folder>)"` and `WSLENV=SUCROSE_DATA_DIR`; start the Portal with `--no-focus`; never synthesize mouse or keyboard input; capture windows only with `.claude/skills/port-feature/capture.ps1` (PrintWindow); stop what you started with `taskkill.exe /IM sucrose-portal.exe /F` and `taskkill.exe /IM sucrose.exe /F` (they match only the Rust binaries, never the C# `Sucrose.*.exe` processes); stop the apps before rebuilding (Windows locks running executables).
- A scratch folder without `Setting/Sucrose.json` makes the service migrate from the real legacy `Setting` folder (read-only, D-03) and play the maintainer's selected theme. When a run must not play a wallpaper, use a folder written by `cargo xtask synth-library` (plan 05), whose prepared settings select nothing and hide the tray.
- Line endings: keep each file's existing endings (`git ls-files --eol <file>`). `.planning/*.md` and `docs/DECISIONS.md` are LF; `docs/FEATURES.md`, `docs/ARCHITECTURE.md`, `docs/MEASUREMENTS.md`, `docs/GPUI.md`, `Cargo.toml`, `deny.toml` and the `crates/sucrose-config/tests/fixtures` files are CRLF in the working tree; `docs/FEATURES.md` has no final newline.
- Before finishing each task: `cargo fmt --all` and the task's verify command. Before finishing the plan: `cargo xtask ci`.
