## Phase Goal

ROADMAP goal (not yet a user story; `/gsd-mvp-phase 3` can convert it, this plan does not invent one): *The service and the Portal work as one app: the user picks a theme in the Portal's library, "Use" applies it through the service, settings migrate from the C# install and persist, and Sucrose can start with the OS.*

This gap-closure plan's slice: **all Sucrose processes talk over one IPC that keeps the service and the Portal single-instance** (ARCH-02): a Portal the service gave up on is told so and reconnects, and it cannot keep the service alive by accident (review WR-04).

<objective>
Fix WR-04: `PortalRegistry::send` sets `registered = None` when `offer` fails, but dropping the `PortalLink` only ends the writer thread; the reader thread of `serve_portal` still holds the other handle of the same pipe, so the Portal keeps showing "connected", gets no events, has its requests ignored, a second Portal may register next to it, and when it finally exits `portals.gone` returns false so `check_exit` is never set. Make the drop disconnect the connection and set `check_exit` for any Portal connection that ends.

Purpose: ARCH-02; review WR-04 ends as fixed.
Output: `Connection::disconnect` (sucrose-ipc) on a `disconnect_pipe` platform helper, the registry and service wiring, tests.
</objective>
