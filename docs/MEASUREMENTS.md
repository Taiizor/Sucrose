**M1 video wallpaper, reading the numbers.** Same theme, same machine, same GPU (NVIDIA GeForce RTX 3050 Laptop GPU for both video renderers, shown by each process's own GPU Engine counters), one active monitor, 300 s average after a 60 s warm-up, measured one app at a time (`cargo xtask measure`; `--row` refuses two different adapters). The Rust renderer reached the RTX 3050 through the GpuPreference value its own service wrote (no manual entry; with `SUCROSE_LOG=debug` the renderer's "video GPU adapter" line (it creates a Direct3D device, so it is not logged at the default level) and the per-process counters name the same LUID 0x00000000_0x0000FAEB). RAM and CPU are at or below the C# MpvPlayer engine: the Rust service plus renderer use 301 MB working set against 596 MB for the three C# processes (505 MB for MpvPlayer + Backgroundog), 1038 MB private against 1215 MB, and 0.40 % CPU against 0.70 %. GPU 3D engine is level: 16.4 % for the Rust renderer against 16.1 % for C# MpvPlayer (R = 1.02, so the mpv options `deband=yes` and `profile=low-latency` stay for parity), with similar GPU memory (719 MB against 733 MB dedicated). The desktop compositor load is also level: dwm.exe 4.2 % (Rust run) against 4.8 % (C# run) on the Intel UHD that drives the internal panel. The first M1 rows (2026-11-22, plan 02-15) compared two GPUs: the Rust renderer ran on the integrated Intel UHD because the GPU preference was not ported yet, the C# MpvPlayer on the RTX 3050; they are replaced by the same-GPU rows above. "Private (commit)" is the sysinfo `virtual_memory()` value, which on Windows is PROCESS_MEMORY_COUNTERS_EX.PrivateUsage. The final M1 build (the row "final M1 build" of 2026-11-23) adds the checked placement read-back, the location watch and the re-place-all rule; in steady state it measured 299 MB working set, 1034 MB private, 0.43 % CPU and 16.4 % GPU against 301 MB, 1038 MB, 0.40 % and 16.4 % for the build of the first 2026-11-23 row, so RAM and GPU are level and CPU is 0.03 percentage points higher (0.43 % against 0.40 %, a difference inside the run-to-run spread of one 300 s sample; peak CPU 1.5 % against 1.1 %). The watch and the read-backs run only at a display change or when explorer moves its desktop window, and none happened during the sample. This row is Rust-only because the C# app was not re-measured: the machine rebooted since the 2026-11-23 C# run, so `--row` refuses to pair it with a renderer on a different LUID; the comparison with C# stays the first 2026-11-23 row.
